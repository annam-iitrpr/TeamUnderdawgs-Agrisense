# Decisions

1. Import the exact inspected existing app snapshot into the empty destination. Exclude README/environment files and unreviewed historical objects. Preserve source attribution in contract handoff.
2. Publish `contract_v1` early, as requested, while reserving `agrisense-contract-v1` for the fully verified bootstrap gate.
3. Keep Phase 1/2-owned paths unchanged after initial import. All interface changes are additive and regenerated by Phase 3.
4. Supplied secrets remain outside Git; scanner compares staged contents against local secret values without printing them.
5. Disable inherited unauthenticated legacy routes in the new application entrypoint; any compatibility adapter must authorize using the same Firebase path.

6. The Cloud Run runtime uses a dedicated `agrisense-api` service account with only
   `cloudsql.client`, `firebaseauth.viewer`, bucket-scoped `storage.objectAdmin` and
   self-scoped `serviceAccountTokenCreator`. The pre-existing `agrisense` account holds
   `roles/owner`, which is far too broad for a service that faces the internet.
7. Media lives in a dedicated `agrisense-media-iitm02` bucket with uniform access and public
   access prevention enforced. The Firebase storage bucket named in the environment had never
   been provisioned.
8. Cloud Run allows unauthenticated invocation because authentication is the application's
   own Firebase bearer check; IAM invoker restriction would block real farmers.
9. Cloud Run's frontend reserves `/healthz` and never forwards it to the container. Container
   probes keep using it, and `/livez` was added for external monitoring.
10. Cloud SQL `sslMode` was left at `ALLOW_UNENCRYPTED_AND_ENCRYPTED` at the user's direction.
    The Auth Proxy and the Cloud Run socket both encrypt, and the public IP authorizes no
    networks, so nothing external can reach it today.
